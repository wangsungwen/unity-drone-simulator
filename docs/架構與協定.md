# 架構與協定

## 模組

| 檔案 | 職責 |
|---|---|
| TrainerApp | 場景入口、角色切換、輸入來源、暫停、指令分派 |
| SceneFactory | 程式化產生原創四軸、地面、起降點與環境 |
| DroneMotor | FixedUpdate Rigidbody 控制與起降狀態 |
| TouchStick | 每支搖桿鎖定個別 pointer ID、圓形行程限制、回中 |
| TrainerHud | UGUI、safe area 適配、觸控控制與繁體中文文字 |
| FlightCamera | 追蹤、地面、機頭三種攝影機 |
| PracticeCourse | 級別、航點順序、航向、5 秒連續停懸、程序卡與緊急返航 |
| RemoteLink | 主執行緒非阻塞 UDP，角色、握手、回報、逾時 |
| Core/ControlLogic | 無 Unity 相依的通道映射、封包門檻及停留計時 |
| Editor/TrainerBuild | 專案設定、平台建置、iOS plist |
| Editor/PlaySmoke | Unity 執行階段／UDP loopback 測試入口 |

所有通訊均於 Unity 主執行緒 Update 讀取；沒有背景執行緒呼叫 Unity API。每幀最多接收 64 個 datagram，單包最多 2048 bytes。UDP 不負責圖像串流。

## 通道定義

值域 `[-1, +1]`。`throttle` 正為上升；`yaw` 正為向右轉；`pitch` 正為沿機頭前進；`roll` 正為機體右移。手機先做 deadzone、手別與靈敏度映射，再傳送標準通道；電腦不再重複套用靈敏度。收到 NaN、Infinity 或超界值的控制封包會丟棄。

## UDP v1

主機綁定 `0.0.0.0:47777`，手機使用 OS 指派的本機埠，手動指定電腦 IPv4。UTF-8 JSON；正式格式以 `WirePacket` 為準。

1. 主機按「啟動接收」，產生新六位配對碼。
2. 手機傳 `hello`，帶 `version=1`、`code`、隨機 `nonce`，每 250 ms 重試，5 秒無回應結束。
3. 主機只接受目前配對碼及未被占用的連線，固定來源 IP＋port，回 `welcome`，帶相同 `nonce` 與新隨機 `session`。
4. 手機驗證來源、nonce，之後只送帶 session 的 `control`，30 Hz。
5. 主機只接受來源端點、session、遞增 sequence 都匹配的控制封包，10 Hz 回 `state`。
6. 有效新封包間隔超過 0.6 秒關閉 session 與 socket，輸入歸零，需人工重新啟動接收與配對。`bye` 主動關閉也會撤銷控制權。

控制示例：

```json
{"version":1,"kind":"control","session":"握手回傳值","sequence":12,"input":{"throttle":0,"yaw":0,"pitch":0.5,"roll":0},"action":1,"command":"takeoff"}
```

`action` 是每個 session 的遞增指令序號。手機持續附帶最後指令直到 state 的 `ackAction` 確認；同一 action 主機最多處理一次。等待確認時不接受下一個按鈕指令。允許的指令為 `takeoff`、`land`、`reset`；非識別指令不影響飛行。

state 的 `height` 單位 m、`speed` 為 m/s、`heading` 為度，並含 `flying`、`crashed`、`task`。兩端各自用接收端單調時鐘計算逾時，不依賴同步時間。

## 使用邊界與擴充

協定只用於同一受信任區域網路，沒有 TLS／DTLS、遠端登入、網際網路穿透或真機 API。六位配對码只防止誤連，無法抵抗區域網路上的竊聽或主動攻擊。要跨不受信任網路需另增驗證與加密。

機體物理採簡化速度控制，不含完整馬達推力、姿態 PID、電池與氣動模擬。若要校準真實機型，可先將 DroneMotor 的上層輸入與底層動力模型分離，再以量測曲線替換速度追蹤器。

目前練習路線寫在 PracticeCourse.Configure。若需不同考級或年度，建議改用 ScriptableObject 保存航點、半徑、停留時間、朝向與扣分規則；現行依據與實作差異見「術科項目對照.md」。
